# 轨迹一致性分析工具集

对 Android World 评测框架下同一任务在 **相同/不同随机种子** 下多次运行的轨迹进行**一致性分析**，
量化 LLM Agent 行为在不同运行条件下的稳定性和复现性。

---

## 整体流程

```
并行任务执行层                   分析管道
┌─────────────────────┐   ┌──────────────────┐
│ parallel_runner_vllm │──▶│ analyze_consistency  │──▶ trajectory_consistency_chart.png
│        ↓            │   │                  │──▶ trajectory_analysis_report.txt
│    run.py (单次)     │   │                  │──▶ trajectory_consistency.json
│        ↓            │   │                  │──▶ unknown_actions_report.txt
│  trace.json + images │   └──────────────────┘
└─────────────────────┘   ┌──────────────────┐
                           │ visualize_trace   │──▶ grouped_report.html (带一致性标签)
                           └──────────────────┘
```

## 一、任务执行层

### run.py
Android World 官方的单次评测入口。

**关键命令行参数：**

| 参数 | 说明 |
|------|------|
| `--tasks` | 指定要运行的任务名（如 `--tasks=CreateANote`），不指定则运行全部 |
| `--suite_family` | 套件族，默认 `android_world` |
| `--agent_name` | Agent 名称，如 `m3a_local` |
| `--task_random_seed` | 任务随机种子，控制任务内部的随机性 |
| `--output_path` | 单次运行输出目录 |
| `--fixed_task_seed` | 是否固定种子（多组合运行时） |

运行完成后，`output_path/` 下会生成：
- `trace.json` — 完整动作序列（包含每步的 goal、action、截图路径等）
- `images/` — 每步操作前后的截图
- `xmls/` — 每步操作前后的 UI 层次 XML

### parallel_runner_vllm.py
多实例并行调度器，基于 vLLM 本地推理服务，统一管理多台 Android 模拟器。

**核心机制：**

1. **模式（Mode）** — 定义一组实验参数，按顺序执行
2. **资源池（Resource Pool）** — 4 组 (adb_port, grpc_port) 对应 4 台模拟器
3. **任务队列** — 从 `all_tasks.txt` 读取所有任务，每 4 个一组并行执行

**模式定义（MODES）：**

| 温度 (temp) | 随机种子 (random_seed) | 模式描述 (desc) |
|:---:|:---:|:---|
| 0.0 | False | `T0.0_FixedSeed` — 低温、固定种子 |
| 0.0 | True  | `T0.0_RandomSeed` — 低温、随机种子 |
| 1.0 | False | `T1.0_FixedSeed` — 高温、固定种子 |
| 1.0 | True  | `T1.0_RandomSeed` — 高温、随机种子 |

**随机种子规则：**
- `random_seed=False`（FixedSeed）: 所有并行实例使用 `seed=0`
- `random_seed=True`（RandomSeed）: 每个实例使用 `seed = timestamp + worker_id`（唯一且不可复现）

**温度的作用：**
- `temp=0.0`: LLM 输出确定性高，greedy decoding，每次相同输入得到相同输出
- `temp=1.0`: LLM 输出有随机性，相同输入可能得到不同输出

**执行流程（每个模式）：**

```
① 清空并重建 outputs/、logs/ 目录
② 从 all_tasks.txt 遍历所有任务
   └─ 每个任务启动 MAX_PARALLEL 个进程
      └─ run_single_instance()
         ├─ 启动模拟器（从快照恢复）
         ├─ 设置 ADB + gRPC + 无障碍服务
         ├─ 运行 run.py（注入 LLM_TEMPERATURE、随机种子）
         ├─ 等待 run.py 结束
         ├─ 关闭并清理模拟器
         └─ 记录执行日志到 task_summary.log
③ 所有任务完成后，整理 outputs/ → 重命名为 outputs-{mode_desc}
④ 进入下一个模式
```

**典型输出目录：**

```
outputs-T0.0_FixedSeed/
├── Create a note_timestamp_1/      ← 每个实例一个目录
│   ├── trace.json                  ← 完整轨迹
│   ├── images/
│   │   ├── 0_before.jpg
│   │   ├── 0_after.jpg
│   │   └── ...
│   └── xmls/
│       └── 0_before.xml
├── Create a note_timestamp_2/
│   └── ...
├── Create a note_timestamp_3/
│   └── ...
└── logs/
    ├── Create a note_w0_timestamp.log  ← 执行日志
    ├── Create a note_w1_timestamp.log
    └── task_summary.log               ← 任务状态汇总
```

## 二、分析管道

### run_analysis.py — 一键分析入口

依次调用 `analyze_consistency.py` 和 `visualize_trace.py`，生成全部报告。

```bash
python run_analysis.py                           # 分析当前目录下所有 outputs-* 目录
python run_analysis.py --dir /path/to/data       # 分析指定目录
python run_analysis.py --dirs dir1 dir2          # 分析多个目录
python run_analysis.py --skip-html               # 跳过 HTML 生成
python run_analysis.py --skip-chart              # 跳过一致性分析
```

### 1. 轨迹一致性分析（analyze_consistency.py）

#### 核心概念

将同一任务在同一模式下多次运行的轨迹进行**动作序列折叠对比**，判断其行为一致性。

#### 什么是"折叠动作序列"？

原始轨迹中的每个 step 包含一个 `action` 字段，形如 `action_type='click' data={'element': {...}}`。
为了去除不影响语义的细节差异（如点击坐标的微小偏移），只保留 **动作类型 + 方向** 作为签名：

```
click, scroll_down, input_text, open_app, long_press, swipe_left, status, answer, ...
```

相邻的相同动作类型被**折叠合并**（例如连续两次 `click` 只计一次），形成精简后的**折叠动作序列**。

#### 目录发现规则

自动扫描以 `outputs-` 开头的目录。目录名中的温度值通过正则 `[Tt](\d+(?:\.\d+)?)` 提取，
种子模式根据目录名中的关键字判断。

#### 任务匹配

每个 `trace.json` 中的 `goal` 字段通过 `task_matcher_utils.get_task_info_by_goal()` 与
预定义的任务模板进行模糊匹配，得到 `task_name`。同一 `task_name` + 时间戳聚类（180 秒阈值）
内的多条轨迹被视为同一实验组。

#### 一致性分类规则

| 类型 | 条件 | 颜色 |
|:---|:---|:---:|
| **严格一致** (type=0) | 实验组内所有折叠动作序列完全相同 | 🟢 绿色 |
| **高度相似** (type=1) | (a) >=3 条轨迹时，n-1 条一致 + 1 条偏差（差异步数 ≤ 3）<br>(b) 所有两两比较差异步数 ≤ 3 | 🟠 橙色 |
| **严重分歧** (type=2) | 不满足上述条件 | 🔴 红色 |

**差异步数 = 不同步数 + 长度差**

#### 输出文件

| 文件 | 说明 |
|------|------|
| `trajectory_consistency_chart.png` | 每组实验的严格/相似/分歧柱状图 |
| `trajectory_analysis_report.txt` | 详细文本报告，列出每个实验组的分类结果 |
| `trajectory_consistency.json` | 按轨迹 ID 索引的一致性 JSON，供 HTML 可视化使用 |
| `unknown_actions_report.txt` | 无法解析的动作统计 |

### 2. 分组轨迹可视化（visualize_trace.py）

生成交互式 HTML 报告，可逐组浏览所有轨迹的详细步骤。

**特性：**
- 侧边栏列出所有实验组，显示任务名、轨迹数、**一致性标签**
- 搜索过滤（按任务名、goal 等关键词）
- 主内容区以列为单位展示每条轨迹的完整执行步骤
- 每步操作自动标注动作类型（点击、输入、滚动等）
- 操作区域（click/input_text 等）在截图上用红色边框高亮
- scroll/swipe 方向用箭头标注
- input_text 内容在截图旁显示文字标注
- 操作完成/失败状态标记

**一致性标签在 HTML 中的显示位置：**
- **侧边栏**：每个 group-item 的 task_name 下方，彩色标签直接可见
- **主内容**：group-header 中 group-stats 行下方

### 3. 总索引页（index.html）

汇总所有分析结果，顶部列图像缩略图，可点击直达完整报告。

## 三、关键技术点

### 时间戳聚类

```python
cluster_traces_by_timestamp(traces, time_threshold_seconds=180)
```
- 先按 `task_name` 分组
- 同一组内按轨迹目录名中的时间戳排序
- 时间差 <= 180 秒的轨迹合并为同一实验组
- 不同批次的同任务自然被分开

### task_name 模糊匹配

通过 `get_task_info_by_goal()` 对 `goal` 文本进行模式匹配，映射到标准化的 `task_name`。
如果任务名缺失，还会用 `get_short_task_label()` 生成简短标签。

### vLLM 本地推理

`parallel_runner_vllm.py` 通过 SSH 隧道连接到本地 vLLM 服务，通过 OpenAI 兼容接口
调用大模型。环境变量 `LLM_TEMPERATURE`、`OPENAI_API_BASE` 等控制推理参数。
每台模拟器有独立的 `TMPDIR` 避免缓存冲突。

## 四、快速开始

### 前置条件

- Python ≥ 3.10
- Android SDK + 已配置好 Android World 模拟器快照
- vLLM 服务运行中（本地或远程）
- `all_tasks.txt` 文件包含待评测任务列表（每行一个任务名）

### 运行任务

```bash
# 四路并行评测（按 MODES 顺序依次执行）
python parallel_runner_vllm.py

# 或单次运行
python run.py --tasks=CreateANote --agent_name=m3a_local --output_path=./my_run
```

### 分析结果

```bash
python run_analysis.py
# 自动扫描 outputs-* 目录，生成 chart + HTML + JSON + 索引
```

### 查看报告

- 打开 `index.html` 查看总索引
- 打开 `outputs-*/grouped_report.html` 查看带一致性标签的轨迹可视化
- 查看 `trajectory_consistency_chart.png` 获取整体一致性概览
